# KISS + YAGNI（强制）

## KISS — Keep It Simple, Stupid

**能用简单方案解决的，不用复杂方案。代码是写给人读的。**

### 硬性指标（超出需要有理由）

| 指标 | 上限 |
|------|------|
| 函数长度 | ≤ 40 行（不含空行和注释） |
| 文件长度 | ≤ 300 行 |
| 函数参数 | ≤ 3 个；更多时用对象参数 |
| 嵌套层级 | ≤ 3 层 |
| 圈复杂度 | ≤ 10 |
| 单个布尔参数 | 避免；用两个命名清晰的函数或枚举代替 |

### 写法要求

- **早返回**代替深层嵌套：先处理异常 / 边界情况，再写主流程
- **命名即文档**：变量、函数名要能说清意图，不用缩写（`cfg`、`mgr`、`tmp2` 这类禁止）；需要注释解释"是什么"时，先考虑改名
- 注释只写**为什么**，不写**做了什么**
- 优先用语言 / 标准库 / 已选框架自带的能力，不重复造轮子
- 不写"聪明"的代码：一行链式魔法、隐式类型转换、元编程、反射，只有在显著降低复杂度时才用
- 数据流要直：一个值从哪来、到哪去，顺着读就能看懂；避免隐式全局状态和事件满天飞
- 引入新依赖前先问：标准库能不能做？这个依赖值不值它带来的维护和安全成本？

```ts
// ❌ 嵌套 + 隐式意图
function pick(t) {
  if (t) { if (t.cu) { if (models.some(m => m.c.includes('cu'))) { return models.find(m => m.c.includes('cu')) } } }
}

// ✅ 早返回 + 清晰命名
function selectModelForTask(task: Task): Model | undefined {
  if (!task.requiresComputerUse) return defaultModel;
  return models.find((model) => model.capabilities.computerUse);
}
```

## YAGNI — You Aren't Gonna Need It

**只实现当前需求明确要的东西。不为想象中的未来写代码。**

- 不写没有调用方的函数、参数、配置项、扩展点
- 不预留"以后可能要支持"的抽象层；等第二个真实需求出现再抽（与 `02-dry.md` 的三次法则一致）
- 不提前做性能优化；先写清楚，有测量数据证明是瓶颈再优化
- 不保留注释掉的代码、废弃的分支、"暂时不用"的文件——版本控制会记住它们
- MVP 阶段严格按 `docs/PRD.md` §9 里程碑推进：先做完 MVP 范围，不提前实现 v0.2+ 的功能（多 runtime 路由等）

### YAGNI 和 OCP 的平衡

OCP 要求"对扩展开放"，YAGNI 要求"别预留用不到的扩展"。取舍规则：

- **架构级扩展点**（`docs/PRD.md` §7 架构中已明确规划的：runtime adapter 接口、skill 加载机制、路由策略）→ 按 OCP 从一开始就留接口
- **其他所有地方** → 按 YAGNI，先写最直接的实现，需要时再重构

## 复杂度必须被证明

引入以下任何一项前，必须在 PR / 提交说明中写明理由：

- 新的抽象层、基类、泛型框架
- 新的第三方依赖
- 缓存、队列、并发 / 多进程
- 插件机制、DSL、代码生成
- 设计模式（工厂、策略、观察者……）——模式是用来解决已存在的问题的，不是用来展示的
