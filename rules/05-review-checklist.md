# 提交前自检清单（强制）

每次写完 / 改完代码，提交前逐条过一遍。任一项答"否"，先改再提交；确需例外，按 `00-overview.md` 在代码中写明原因。

## SOLID
- [ ] 每个新增 / 修改的模块只有一个变化的理由？
- [ ] 新增 runtime / skill / 路由策略时，没有修改核心流程里的分支？
- [ ] 所有 adapter 实现都遵守同一份接口契约，并通过契约测试？
- [ ] 接口足够小，调用方没有被迫依赖用不到的方法？
- [ ] core 没有 import 任何具体 SDK / 系统库？依赖是注入的？
- [ ] 没有引入循环依赖，依赖方向符合 `TUI → core ← adapters/infra`？

## DRY
- [ ] 常量、配置、类型、业务规则都只有一个权威来源？
- [ ] 安全相关判断（权限、确认、审计）没有出现第二份实现？
- [ ] 没有为了去重而引入 flag 参数或破坏模块边界的"伪 DRY"？

## KISS / YAGNI
- [ ] 函数 ≤ 40 行、参数 ≤ 3 个、嵌套 ≤ 3 层、文件 ≤ 300 行？
- [ ] 命名清晰，读代码不需要额外解释？
- [ ] 没有无调用方的代码、注释掉的代码、预留的"未来扩展"？
- [ ] 新增的抽象 / 依赖 / 设计模式都有明确理由？

## 其他
- [ ] 纯逻辑和副作用分开了？TUI 里没有业务逻辑？
- [ ] 没有吞异常？边界输入都做了校验？
- [ ] 危险操作（computer use、shell、删除）默认需要确认？
- [ ] 改动附带了测试，或说明了为什么不需要测试？

## Changelog
- [ ] feature / 行为变化 / 修复 / 安全改动已在 `CHANGELOG.md` 的 `[Unreleased]` 下补上条目（见 `06-changelog.md`）？
- [ ] 条目以模块名开头、从使用者视角描述，破坏性变更标了 `**BREAKING**` 并写了迁移方法？

## 子目录 AGENTS.md
- [ ] 新建或长大到满足条件的大功能模块 / component / 多 provider 目录，已按 `07-nested-agents-md.md` 模板补上 `AGENTS.md` 和一行 `@AGENTS.md` 的 `CLAUDE.md`？
- [ ] 改动涉及契约、不变量、扩展方式时，对应目录的 `AGENTS.md` 已同步更新？
